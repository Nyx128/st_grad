# ST-GRAD Anonymous Repository Audit

**Audit subject:** uploaded `ST-GRAD-Stock-Prediction-6E7D.zip`  
**Paper:** Fu, Huang, and Yu (2026), *ST-GRAD: Multi-view cross-attention and bidirectional diffusion for stock trend prediction*, *Expert Systems With Applications* 330, 133046. DOI: [10.1016/j.eswa.2026.133046](https://doi.org/10.1016/j.eswa.2026.133046).  
**Archive SHA-256:** `690ed2f727a588bb71b6f74c863396a2a2dd129d0c99de8441ec04889a012434`

## Executive assessment

The archive is a useful code/checkpoint release, but it is **not a complete, self-contained reproduction of all experiments in the paper**. Its core network can run, the parameter counter returns the paper's reported 216,429, and the supplied `best_model_ours.pth` obtains near-paper metrics when evaluated on data generated by the bundled processor. However, several core data/model operations differ from the methodology as printed, and important experimental scripts are absent. Preserve the implementation as a compatibility reference while developing a distinct paper-aligned path.

The ZIP does not contain `.git` metadata. The archive hash above pins the inspected bytes, but no commit hash can be inferred from the ZIP contents.

## 2. Repository execution and sanity checks

The following checks were run against the extracted archive:

1. Confirmed that all 50 ticker CSVs have 1,255 rows and the expected six fields: `date`, `open`, `high`, `low`, `close`, `volume`.
2. Confirmed `stock_order.npy` and the stock order in `cluster_results.csv` match.
3. Confirmed the supplied graph is `50 × 50`, symmetric within floating-point precision, with row sums approximately one.
4. Ran the source processor on the bundled data. The resulting arrays are `X_train [856,30,50,24]`, `y_train [856,50,1]`, `X_val [368,30,50,24]`, and `y_val [368,50,1]`; the 70/30 sample counts match the paper's first-stage split.
5. Instantiated and ran a CPU forward/backward pass for input `[2,24,30,50]` and a `[50,50]` graph. Output shape was `[2,50]`. `sum(p.numel() for p in model.parameters())` returned `216,429`.
6. Confirmed the third diffusion weight tensor in each ST-Block has `grad is None` after backward.
7. Evaluated both supplied checkpoints on the regenerated 368-sample validation set. Metrics are reported in Section 6.

## 3. Data pipeline audit (`utils/data_processor.py`)

### 3.1 Feature set

The code produces the intended count of 24 technical features from OHLCV. Most names correspond to the features listed in Table 5, though the ordering differs from the paper's grouped table. Important implementation details:

- `calculate_indicators()` calculates `Relative_Close`, `OC_Ratio`, `VWAP`, RSI and scaled RSI, normalized MACD histogram, volume ratio, ROC, momentum, moving-average gap, Bollinger features, ATR, volume change, close-in-range, volatility, return/volume correlation, volume momentum, price acceleration, high/low ratio, close/MA ratio, sector-relative strength, and volatility ratio.
- The code fills data early with forward fill and zero fill; it does not persist an original-missingness/validity mask.
- `VWAP` is coded as `(TP.rolling(30).sum() + volume * close) / (volume.rolling(30).sum() + volume)`. It does not calculate the usual trailing sum of `TP * volume` divided by trailing sum of volume. The paper's Table 5 formula is itself visually ambiguous and appears to include an extra current-day term, so document both interpretations before changing it.
- `ATR` is an absolute-price-scale feature even though the paper broadly characterizes all inputs as stationary/scale-normalized. The code does not prove statistical stationarity.
- `Sector_Relative_Strength` is calculated per ticker as five-day momentum minus a 10-day rolling mean of that same feature; it does not aggregate stocks by sector.

### 3.2 Label construction is not paper-faithful

`FEATURES[0] == 'Relative_Close'`, but `create_labels()` uses the first feature channel to calculate `current`, `next_day`, and `avg_price`. That means the implementation uses relative-close ratios rather than raw `Close` as `P_(i,t+1)` and `Pbar_(i,t)` in Eq. (29). `raw_data` currently stores only the features, not a dedicated close-price matrix. Keep a raw close sidecar for label construction; do not add absolute close as an input feature.

The paper's threshold is `T_(i,t) = T_base * (1 + k * tanh(abs(volume_pct)))`. Code uses `tanh(abs(volume_pct) * 8)`, introducing an extra factor of eight. Code also initializes all labels to zero and sets positive labels only for rows where `abs(volume_pct) >= 0.003`; no target mask is saved. Nodes that should be excluded can be counted as negative examples in training and metrics.

The source's sample counts match 856/368 after selecting 1,224 labeled date-windows. It builds one additional input window and then slices that away. It does not expose a separate inference path for a final unlabeled window if the last date is held out for prediction.

### 3.3 Normalization convention

The saved normalization arrays have shape `[1,1,50,1]`: one mean and standard deviation per ticker, pooling together time and all 24 different feature channels. This differs from per-feature normalization and can mix incompatible feature scales. The paper's equation states Z-score normalization but does not fully specify axes; this must be a named configuration option and logged deviation. Also, validity checks are performed after `np.nan_to_num`, so they generally cannot detect original invalid entries.

## 4. Graph construction audit (`utils/graph_builder.py`)

The code does not implement the paper's deep behavioral graph-construction process. It reads `cluster_results.csv`, takes `Trend`, connects `i` and `j` if their labels match or they are the same stock, and applies symmetric normalization. `Hierarchical` is ignored. Supplied `Trend` cluster counts are `{1:30, 4:10, 2:5, 5:4, 3:1}`. No code records what encoder generated them, the dates used to train the encoder, its latent representation, the K-Means random seed, or its scaler. As such, the included graph is reproducible from included cluster labels, but the clustering process is not reproducible from OHLCV alone.

Because the adjacency generated from class membership is symmetric, its transpose is identical. The source model's use of both `A` and `A.T` therefore duplicates static graph propagation for this graph (the adaptive graph may remain asymmetric). This is relevant when interpreting “bidirectional” diffusion.

## 5. Architecture audit (`models/st_grad.py`)

### 5.1 What works

- `ST_GRAD(24, 1, 50, 30, 32, 2, 2, 10)` instantiates and forwards `[B,24,30,50]` to logits `[B,50]`.
- The architecture includes BatchNorm and an initial 1×1 projection; four-head temporal self-attention; ST/DS/DT readouts and U-D gates; learnable softmax view-fusion scalars; adaptive node embeddings; graph propagation; residual conv/layer norm/ReLU; and a pointwise output decoder.
- Reported parameter count is exactly 216,429, matching Table 7.

### 5.2 MVCA changes the model function

The paper's equations use a trainable `Conv2d_1×1` signal transformation before `tanh` and gated modulation. The source uses `F.conv2d` with `torch.ones(...)` filters in all three signal branches. These are constant, non-trainable summations; they do not have learned filter parameters.

The resulting ST signal tensor has shape `[B,1,T,N]`; DS has `[B,D,1,N]` before fusion; DT has `[B,D,T,1]` before fusion. Addition at fusion time uses implicit broadcasting to yield `[B,D,T,N]`. This is not the same as producing a learned full-shaped view representation before fusion. Parameter-count equality therefore does not validate the mathematical implementation.

For `T=30`, DS splits the sequence into 15 chunks of length 2; this patching detail is not fully specified in the paper. Odd sequence lengths may not match the expected U-D input channel count.

### 5.3 Diffusion parameter issue

`DiffusionConvolution.__init__()` allocates `max_diffusion_step + 1` weights. The forward loop iterates `range(max_diffusion_step)`. At `K_diff=2`, only indices 0 and 1 are used; the weight at index 2 is dead and gets no gradient. Eq. (24) in the paper sums `j=0` through `K_diff-1`, so a paper-aligned implementation should allocate exactly the weights it uses unless further source evidence argues otherwise.

The source correctly creates the adaptive adjacency from the ReLU of two embedding matrices' inner product, adds epsilon, and applies row-wise softmax. It uses the learned adaptive matrix only in the `j=0` contribution. This matches the equation's placement more closely than some other details of the pseudocode.

### 5.4 Hierarchical fusion

Paper Algorithm 2 initializes `layer_outputs` with the initial projection `X^(0)` before appending each ST-Block output. Source code initializes `layer_outputs = []`, appends the block outputs, then calculates `x_out = x + sum(layer_outputs)`. It omits `X^(0)` from the sum. Algorithm 2's stated `X_out = X^(L) + X_sum` also appears to count the final block twice, so use an explicit named interpretation rather than quietly choosing a simplified sum.

`nn.LayerNorm([D,T,N])` applies layer normalization over all non-batch dimensions; the equation does not fully define the axes. Preserve this in compatibility mode; report it explicitly if changed.

## 6. Training and checkpoint audit

### 6.1 Differences from paper protocol

- One run with global seed 43; paper reports five independent runs.
- Uses `BCEWithLogitsLoss` with `pos_weight=(1-mean(y_train))/mean(y_train)`. Table 7 does not describe this weighting.
- Training `DataLoader` has `shuffle=False`.
- No early stopping; it always reaches the configured epoch count while saving any best validation-F1 checkpoint.
- `ReduceLROnPlateau` adjusts learning rate based on validation F1.
- `test_model()` evaluates on the same 368-sample validation set that drove checkpoint choice; this is not a blind test.
- No separate first-307/last-61 split for clean validation and high-volatility stress evaluation.
- No complete baseline, ablation, hyperparameter sensitivity, graph-comparison, or orthogonality implementation is included.

The README is inaccurate when it says early stopping is applied. The `main.py --mode all` shortcut checks only whether artifact files exist, so stale files can be silently reused after source or data changes. Add a cache manifest keyed to input hashes, code version, config and seed.

### 6.2 Checkpoint metrics on regenerated source dataset

The dataset was regenerated with the source processor. The existing weights were then evaluated on the generated validation partition using the source network and standard binary classification metrics:

| Checkpoint | Accuracy | Precision | Recall | F1 | AUC |
|---|---:|---:|---:|---:|---:|
| `best_model_ours.pth` | 0.8317 | 0.7651 | 0.8911 | 0.8233 | 0.9041 |
| `st_grad_best_model.pth` | 0.8268 | 0.7596 | 0.8874 | 0.8185 | 0.9038 |
| Paper Table 8 | 0.8313 ± 0.0018 | 0.7705 ± 0.0063 | 0.8799 ± 0.0078 | 0.8215 ± 0.0009 | 0.9046 ± 0.0003 |

This near-match shows the pretrained weights are compatible with the bundled pipeline and that the repository likely reflects the results pipeline closely. It does not prove paper-faithful reproduction because the label formula is not the paper formula, and the same validation partition is used for model selection/evaluation. The environment used for this audit was CPU-only with `torch 2.10.0+cpu`, not the paper's PyTorch 2.4.1/CUDA 12.1.

## 7. Recommended agent implementation plan

### Phase 0 — Freeze and reproduce source behavior

1. Store ZIP SHA-256 in `docs/source_manifest.md`; note that no Git commit can be identified.
2. Create `configs/repo_compat.yaml` and capture seed 43, raw stock order, feature order, source labels, graph file, model config and weighted BCE.
3. Run `python main.py --mode data` and ensure the generated NPZ has the expected arrays and shapes.
4. Load both checkpoints and produce a structured metric report on the repository validation set.
5. Write tests that explicitly reproduce target formula, view-shape/broadcasting behavior, dead diffusion weight and hierarchical fusion behavior. Mark these tests as compatibility tests, not correctness tests.

### Phase 1 — Implement paper-aligned data without changing the baseline

1. Add raw `close` sidecar per `(date, ticker)` and construct labels from it.
2. Implement Eq. (28) literally; remove the extra factor eight from the paper-aligned path.
3. Add target validity masks and make training/evaluation mask-aware; never encode invalid observations as class zero by default.
4. Define the 30-day close averaging window as a logged assumption if no original source explains it.
5. Resolve the Table 5 VWAP expression explicitly; expose `paper_table_literal` and `conventional_vwap` variants if ambiguity remains.
6. Make feature scaling axis an explicit configuration. Compare per-stock pooled scaling (source) with per-feature training-only scaling and explain the chosen paper-aligned setting.
7. Save window input-end date, target date, split name, stock order, target mask, `train_mean/std`, feature order and raw-data hash in the dataset manifest.

### Phase 2 — Implement paper-aligned model operators

1. Replace hard-coded all-ones `F.conv2d` operations in MVCA signal branches with learned 1×1 `nn.Conv2d` modules and explicit shapes. Test ST, DS, and DT view outputs before fusion and assert shape compatibility; avoid accidental broadcasting.
2. Allocate only used diffusion parameters for the equation's `j=0..K_diff-1` range; add unit tests for identity, first-order and transpose propagation. If reproducing the paper's `K_diff=2`, decide whether there are two polynomial terms or two neighbor hops and log that interpretation.
3. Compare the source LayerNorm axis to a channel-wise alternative only as a named sensitivity test.
4. Include the initial projection in hierarchical fusion according to Algorithm 2; run both literal-algorithm and unambiguous skip-sum variants if resolving the double-final contribution is necessary.
5. Count trainable and gradient-active parameters separately; don't add unused parameters to match the published count.

### Phase 3 — Full experimental protocol

1. Restore the described clean validation/stress isolation: 307 clean-validation samples and 61 stress samples inside the 368-row out-of-sample partition, with exact dates documented. The paper's description should be reconciled against the source data calendar.
2. Use five independent seeds; write one row per seed and a mean/std aggregate. Do not use the stress set for checkpoint selection or hyperparameter tuning.
3. Reproduce the graph comparison, Table 9 ablations, the `(L,K_diff)` sensitivity grid, Table 10 resource measurements, pairwise view cosine/MI, and Table 12 stress test.
4. Implement each baseline or report that it cannot be faithfully reproduced because the architecture/code/config is missing. Do not substitute a differently configured baseline without labeling it.
5. Export raw predictions, labels/masks, run metadata, checkpoint hashes, confusion matrices, ROC curves, metric tables and plots from scripts (not static copied images).
